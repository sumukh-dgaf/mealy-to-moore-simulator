      1. Problem Definition & Automata Specification

      Problem

      Mealy and Moore machines are the two standard finite-state transducers. Textbooks prove they are equivalent, but students usually see the conversion only as a finished table: not why a Mealy state must be split, which copy becomes the start state, or how to check that the result really behaves the same. A hand conversion can also be wrong in ways a few test strings miss.

      Objectives

      1. Accept any user-defined deterministic, complete Mealy machine and validate it with a clear message for every error.
      2. Convert it to an equivalent Moore machine by state splitting, reproducing hand-worked examples exactly.
      3. Show every step (incoming outputs, created states, transitions, start choice, pruning) with the rule applied.
      4. Draw the Mealy and Moore machines and their transition tables.
      5. Prove equivalence with an exact algorithm that returns a shortest counterexample, and test user and random strings.

      Formal specification

      Input: a Mealy machine M = (Q, Σ, Δ, δ, λ, q₀): Q finite states, Σ input alphabet, Δ output alphabet, δ : Q × Σ → Q, λ : Q × Σ → Δ (output on transitions), q₀ ∈ Q. On input of length n it outputs n symbols.

      Output: a Moore machine M′ = (Q′, Σ, Δ, δ′, λ′, q₀′) with λ′ : Q′ → Δ (output on states). On input of length n it outputs n + 1 symbols; the first, λ′(q₀′), is printed before any input is read.

      Equivalence convention: M and M′ are equivalent iff for every w ∈ Σ*, the Moore output of w with its first symbol dropped equals the Mealy output of w, i.e. λ′(δ′*(q₀′, u·a)) = λ(δ*(q₀, u), a) for all u ∈ Σ*, a ∈ Σ.

      Why split states: a Moore state has one output, but a Mealy state can be entered by transitions with different outputs (q1 in Example 1 is entered with 0 and with 1). Each copy [q, o] remembers “in q, last output o”.

      4. Algorithm Selection & Pseudocode

      Algorithm A: Mealy → Moore (state splitting)

      MEALY-TO-MOORE(M, def = Δ[0], startOut = none, prune = true):
  for each q, a:  O(δ(q,a)) ← O(δ(q,a)) ∪ {λ(q,a)}                ▷ A1
  for each q:
      if O(q) = ∅:  create [q,−] with λ′ = def                      ▷ A3
      else for each o ∈ O(q):  create [q,o] with λ′ = o             ▷ A2
  for each [q,o], a:  δ′([q,o], a) ← [δ(q,a), λ(q,a)]               ▷ A4
  q0′ ← [q0,−] if O(q0) = ∅ else [q0, startOut or first of O(q0)]   ▷ A5
  if prune: keep only states reachable from q0′ (BFS)               ▷ A6
  return M′                                     ▷ |Q′| ≤ |Q|·|Δ|

      Why it is correct: the target in A4 always exists, because λ(q,a) was added to O(δ(q,a)) in A1. By induction, after reading u·a the Moore machine is in [δ*(q0, u·a), λ(δ*(q0, u), a)], whose output is exactly the Mealy output for a. The transitions of [q,o] never depend on o, so every start copy and every default output only changes the first (dropped) Moore symbol.

      Algorithm C: exact equivalence check (formal validation)

      EQUIVALENT(M, M′):
  queue ← [(q0, q0′)];  parent[(q0, q0′)] ← nil
  while queue not empty:
      (q, r) ← dequeue(queue)
      for each a in Σ:
          if λ(q,a) ≠ λ′(δ′(r,a)):  return NOT EQUIVALENT, path(q, r)·a
          if (δ(q,a), δ′(r,a)) unseen:  record parent; enqueue it
  return EQUIVALENT

      Why it is sound and complete: every input prefix leads to exactly one reachable pair, there are at most |Q|·|Q′| pairs, and each check is exactly the convention for one prefix and one symbol. BFS order makes the counterexample a shortest one. This is stronger than random testing.

      5. Manually Solved Validation Example

      Mealy “11” sequence detector over Σ = Δ = {0, 1}, start q0: outputs 1 when the last two inputs are 11. (Load “Example 1” in the Simulator to compare.)

      δ / λ01
      →q0q0 / 0q1 / 0
      q1q0 / 0q1 / 1

      Step A1: outputs entering each state

      TransitionTargetOutput added
      q0 —0/0→ q0q00
      q0 —1/0→ q1q10
      q1 —0/0→ q0q00
      q1 —1/1→ q1q11

      O(q0) = {0}, O(q1) = {0, 1}. So q0 → [q0,0] (output 0); q1 splits into [q1,0] (output 0) and [q1,1] (output 1). No state lacks incoming transitions.

      Steps A4–A6: Moore machine

      δ′λ′01
      →[q0,0]0[q0,0][q1,0]
      [q1,0]0[q0,0][q1,1]
      [q1,1]1[q0,0][q1,1]

      Start = [q0,0] since O(q0) = {0}. All three states are reachable, so nothing is removed. |Q′| = 3 ≤ |Q|·|Δ| = 4.

      Validation by hand: w = 0111

      iReadMealyMealy outputMoore stateMoore output
      0–q0–[q0,0]0 (dropped)
      10q0 → q00[q0,0]0
      21q0 → q10[q1,0]0
      31q1 → q11[q1,1]1
      41q1 → q11[q1,1]1

      Mealy output 0011; Moore output 00011 → drop the first symbol → 0011 ✓.

      Equivalence by hand (Algorithm C): from (q0, [q0,0]): on 0, 0 = λ′([q0,0]) = 0 ✓; on 1, 0 = λ′([q1,0]) = 0 ✓ → (q1, [q1,0]). From (q1, [q1,0]): on 0, 0 = 0 ✓; on 1, 1 = λ′([q1,1]) = 1 ✓ → (q1, [q1,1]). From (q1, [q1,1]): 0 = 0 ✓, 1 = 1 ✓. 3 pairs, no mismatch → equivalent.

      The simulator reproduces exactly these sets, states, transitions and outputs (also asserted in tests/core.test.js). Example 2 covers the edge cases: a state entered with three different outputs, a start state with no incoming transitions, and unreachable copies.
